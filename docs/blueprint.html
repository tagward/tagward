Tagward architecture blueprint

From a tag in OpenMetadata to a denied, masked or filtered query in Trino, through Apache Ranger, with one controller in the middle and no commercial license anywhere in the stack.

Trino · Apache 2.0 Apache Ranger · Apache 2.0 OpenMetadata · Apache 2.0 Keycloak · Apache 2.0 PostgreSQL · OpenSearch Atlas · replaced Gravitino · optional, not in v1

1. The whole system

Four planes. Intent lives in git and OpenMetadata. The controller compiles intent into Ranger. Ranger's plugin inside Trino enforces at query time. Every arrow is one integration we own or configure.

The numbered flows

  1. Ingest. OpenMetadata pulls schema, usage and query-log column lineage from Trino, and OpenLineage events from Spark or Flink. Assets exist in the catalog before anyone classifies them.
  2. Classify. The auto-classifier writes Automated tags in state Suggested. Stewards write Manual tags, which are Confirmed on creation.
  3. Propagate. The controller walks column lineage from every Confirmed sensitive tag and writes Propagated tags in state Suggested, stopping at declassification tags and at the depth the rules allow.
  4. Approve. A human confirms or rejects each Suggested tag in the OpenMetadata UI. Only Confirmed tags reach the compiler.
  5. Compile and apply. Confirmed tags times intents from git produce a plan: Ranger tag definitions, tag-to-resource maps, tag-based access and masking policies, and per-table row-filter policies. The applier writes only objects it owns and removes orphans.
  6. Enforce. The Ranger plugin in the Trino coordinator polls the admin, caches policies, and rewrites or denies each query. Audit goes straight from the plugin to OpenSearch.
  7. Verify and feed back. Conformance tests run real queries as synthetic users. Drift compares intent, Ranger and observed behavior. Status and sensitive-access counts are written back onto each asset in OpenMetadata.

2. Life of a tag

The Atlas features we drop are propagation and the change feed. Both come back as states in this lifecycle, using label types and states that OpenMetadata already has.

3. Gravitino: what it would change

Gravitino is fully open source under Apache 2.0 and a top-level Apache project. The question is not license, it is whether it earns its place in the query path.

Verdict on Gravitino. Not in the first release. It solves catalog federation across engines, not classification-driven policy, and its Ranger authorization plugin still carries documented limitations and a Trino session-user forwarding issue. Adopt it later as an optional asset source, and possibly as a second enforcement target, once multi-engine consistency becomes a requirement.

6. Decisions still open

  • Tag attributes in git, not in OpenMetadata. OpenMetadata tags are flat labels, so expiry, owner group and mask choice are keyed by tag name in the intent files, with per-asset overrides as custom properties.
  • No controller UI. OpenMetadata is the front door, Ranger admin is the operator console, the controller exposes a CLI and a status endpoint.
  • Controller language. Java stays close to the Ranger and Trino client libraries. Go gives one portable binary. Leaning Java for M1.
  • Quarantine default. A new column on a table that carries any sensitive tag is denied to everyone but the owner group until classified. Strict, and the only default that fails safe.
